# پیام‌رسان

پیام‌رسان ساده و سبک برای گفتگو و ارسال عکس، با پنل مدیریت برای تایید کاربران و
پاکسازی خودکار هفتگی داده‌ها.

- **بک‌اند**: Node.js + Express + WebSocket، پایگاه‌داده‌ی SQLite داخلی Node (بدون وابستگی بومی)
- **کلاینت موبایل**: وب‌اپ راست‌چین و PWA (قابل نصب روی اندروید) + اپ اندروید (Kotlin/WebView)
- **بدون سرویس بیرونی**: همه‌چیز روی سرور خودتان اجرا می‌شود

## امکانات

| بخش | توضیح |
| --- | --- |
| گفتگو | پیام متنی دوطرفه و گروهی، پاسخ به پیام، ویرایش و حذف |
| عکس | ارسال عکس از گالری یا دوربین، کوچک‌سازی خودکار پیش از آپلود، نمای بزرگ و دانلود |
| زنده | تحویل آنی پیام، نشانگر «در حال نوشتن»، وضعیت آنلاین، تیک خوانده‌شدن، شمارنده‌ی خوانده‌نشده |
| تایید کاربر | هر ثبت‌نام تازه در حالت «در انتظار» می‌ماند تا مدیر آن را تایید کند |
| پنل مدیریت | آمار، تایید/مسدودسازی/حذف کاربر، تغییر رمز، مدیر کردن، پاکسازی دستی |
| پاکسازی هفتگی | هر ۷ روز همه‌ی پیام‌ها و عکس‌ها حذف می‌شوند؛ حساب‌ها و گروه‌ها می‌مانند |

## اجرا

```bash
npm install
npm start           # روی http://localhost:3000
```

سپس در مرورگر باز کنید و ثبت‌نام کنید. **نخستین حسابی که ثبت‌نام می‌کند به‌صورت
خودکار مدیر و تاییدشده است**؛ بقیه‌ی کاربران باید از پنل مدیریت تایید شوند.

پنل مدیریت: `http://localhost:3000/admin`

### متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
| --- | --- | --- |
| `PORT` | `3000` | پورت سرور |
| `HOST` | `0.0.0.0` | نشانی شنود |
| `DATA_DIR` | `./data` | پوشه‌ی داده‌ها |
| `DB_FILE` | `./data/chat.db` | فایل پایگاه‌داده |
| `UPLOAD_DIR` | `./data/uploads` | پوشه‌ی عکس‌ها |
| `MAX_IMAGE_BYTES` | `8388608` | بیشینه‌ی حجم هر عکس (۸ مگابایت) |

### دستورهای کمکی

```bash
npm test                                   # آزمون سرتاسری (۱۶ آزمون)
npm run create-admin -- boss secret123 رئیس   # ساخت یا ارتقای حساب مدیر
npm run wipe                                # پاکسازی دستی پیام‌ها و عکس‌ها
npm run icons                              # ساخت دوباره‌ی آیکون‌های PWA
```

## پاکسازی هفتگی

زمان‌بند داخل خود سرور اجرا می‌شود (هر ۵ دقیقه بررسی می‌کند) و به کران نیاز ندارد.
اگر سرور هنگام موعد پاکسازی خاموش باشد، در نخستین اجرای بعدی جبران می‌شود.

در هر پاکسازی این‌ها **حذف** می‌شوند: همه‌ی پیام‌ها (متن و عکس) و فایل‌های آپلودشده.
این‌ها **باقی می‌مانند**: حساب‌های کاربری، تاییدهای مدیر، گروه‌ها و عضویت‌ها.

مدیر می‌تواند از پنل، دکمه‌ی «پاکسازی همین حالا» را هم بزند.

## استقرار روی سرور (دسترسی از هر جا)

روی سروری که از قبل سایت دیگری دارد (پورت ۸۰ و ۴۴۳ را نمی‌گیرد):

```bash
sudo bash deploy/deploy-vhost.sh chat.example.com you@mail.com
```

روی سرور خالی، همراه HTTPS خودکار با Caddy:

```bash
sudo bash deploy/deploy.sh chat.example.com you@mail.com
```

راهنمای کامل — شامل استقرار با داکر، nginx، systemd، پشتیبان‌گیری، سرور پشتیبان و
اینکه در هر نوع قطعی شبکه چه چیزی بالا می‌ماند — در [`deploy/README.md`](deploy/README.md).

## نصب روی اندروید

دو راه دارید؛ هر دو به همین سرور وصل می‌شوند.

### ۱) نصب PWA (بدون بیلد)

در کروم اندروید نشانی سرور را باز کنید و از منو «Add to Home screen» را بزنید.
برنامه تمام‌صفحه و با آیکون خودش اجرا می‌شود.

> برای نصب PWA و کارکرد دوربین، سرور باید روی `https` باشد (یا `localhost`).

### ۲) نصب فایل APK آماده

فایل ساخته‌شده و امضاشده: [`dist/messenger-1.0.apk`](dist/messenger-1.0.apk)

آن را روی گوشی کپی کنید و نصب کنید (اجازه‌ی «نصب از منابع ناشناس» لازم است، چون از
گوگل‌پلی نصب نمی‌شود). هنگام نخستین اجرا نشانی سرور را می‌پرسد.

### ۳) بیلد اپ اندروید

پوشه‌ی `android/` یک پروژه‌ی کامل Android Studio است که وب‌اپ را در یک WebView
تمام‌صفحه نشان می‌دهد و انتخاب عکس از گالری/دوربین، دکمه‌ی بازگشت و کشیدن برای
تازه‌سازی را به سیستم‌عامل وصل می‌کند.

```bash
# پوشه‌ی android/ را در Android Studio باز کنید، یا:
cd android
echo "sdk.dir=$ANDROID_HOME" > local.properties
gradle assembleDebug         # خروجی: app/build/outputs/apk/debug/app-debug.apk
```

برای ساخت نسخه‌ی امضاشده‌ی release، فایل `android/keystore.properties.example` را به
`keystore.properties` کپی کنید، مقادیر انبار کلید خودتان را بگذارید و
`gradle assembleRelease` را اجرا کنید. انبار کلید را جایی امن نگه دارید: برای
به‌روزرسانی همان برنامه روی گوشی‌ها، نسخه‌ی بعدی باید با همان کلید امضا شود.

نشانی پیش‌فرض سرور `http://10.0.2.2:3000` است (یعنی `localhost` رایانه از دید
شبیه‌ساز اندروید). برای دستگاه واقعی، هنگام نخستین اجرا نشانی سرور از شما پرسیده
می‌شود و بعداً هم از صفحه‌ی خطا قابل تغییر است. برای تغییر پیش‌فرض، مقدار
`DEFAULT_SERVER_URL` را در `android/app/build.gradle.kts` عوض کنید.

> فایل `gradle-wrapper.jar` در مخزن نیست؛ Android Studio آن را خودش می‌سازد،
> یا با `gradle wrapper` بسازید.

## ساختار پروژه

```
server/
  index.js      راه‌اندازی HTTP، استاتیک و مسیرها
  db.js         شِمای SQLite
  auth.js       رمز، نشست و نگهبان‌های دسترسی (تاییدشده / مدیر)
  store.js      همه‌ی پرس‌وجوهای پایگاه‌داده
  routes.js     API گفتگو، پیام و عکس
  admin.js      API پنل مدیریت
  realtime.js   وب‌سوکت: پخش پیام، حضور، «در حال نوشتن»
  cleanup.js    پاکسازی هفتگی
  images.js     تشخیص فرمت و ابعاد عکس از روی بایت‌ها
public/         وب‌اپ (PWA)، پنل مدیریت، سرویس‌ورکر و آیکون‌ها
android/        اپ اندروید (Kotlin + WebView)
scripts/        ابزارهای خط فرمان
test/           آزمون سرتاسری با node:test
```

## نکات امنیتی

- رمزها با bcrypt ذخیره می‌شوند و نشست‌ها توکن تصادفی ۲۵۶ بیتی دارند.
- فرمت عکس از روی بایت‌های فایل تشخیص داده می‌شود، نه از روی نام یا `Content-Type`.
- دسترسی به هر عکس فقط برای اعضای همان گفتگو ممکن است.
- مسدود کردن یا حذف تایید یک کاربر، بی‌درنگ نشست‌ها و اتصال زنده‌اش را می‌بندد.
- برای استفاده‌ی واقعی، سرور را پشت HTTPS (مثلاً nginx + Let's Encrypt) قرار دهید.
