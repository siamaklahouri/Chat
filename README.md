# پیام‌رسان

پیام‌رسان ساده و سبک برای گفتگو و ارسال عکس، با پنل مدیریت برای تایید کاربران و
پاکسازی خودکار هفتگی داده‌ها.

- **بک‌اند**: Node.js + Express + WebSocket، پایگاه‌داده‌ی SQLite داخلی Node (بدون وابستگی بومی)
- **کلاینت موبایل**: وب‌اپ راست‌چین و PWA (قابل نصب روی اندروید) + اپ اندروید (Kotlin/WebView)
- **بدون سرویس بیرونی**: همه‌چیز روی سرور خودتان اجرا می‌شود

## پیش‌نمایش لینک و امنیت

این تنها جایی است که سرور به **دستور کاربر** به بیرون وصل می‌شود، پس محکم
بسته شده (`server/preview.js`):

- فقط `http` و `https`، فقط پورت ۸۰ و ۴۴۳.
- نشانی به IP تبدیل می‌شود و اگر به شبکه‌ی داخلی، لوکال‌هاست یا متادیتای ابری
  (`169.254.169.254`) اشاره کند رد می‌شود. همین بررسی روی **هر تغییرمسیر** هم
  تکرار می‌شود، وگرنه یک نشانی عمومی می‌توانست به داخل بفرستدمان.
- سقف سه تغییرمسیر، ۵ ثانیه مهلت، فقط ۱۲۸ کیلوبایت اولِ صفحه، فقط `text/html`.
- پاسخ همیشه ۲۰۰ است با مقدار خالی وقتی چیزی پیدا نشد؛ اگر «رد شد» با
  «پیدا نشد» فرق می‌کرد، می‌شد با همان تفاوت شبکه‌ی داخلی را نقشه‌برداری کرد.
- نتیجه در حافظه کش می‌شود و هر کاربر در دقیقه بیست درخواست بیشتر نمی‌تواند.

## زبان

رابط کاربری دو زبانه است و انتخاب زبان در «ظاهر» است. پیش‌فرض فارسی است و
انتخاب کاربر روی همان دستگاه می‌ماند.

کلیدِ هر رشته در `public/js/i18n.js` **خودِ متن فارسی** است، نه شناسه‌ای مثل
`login.title`. دو دلیل دارد: اگر ترجمه‌ای نباشد کاربر متن فارسی می‌بیند نه یک
کلید خام، و جابه‌جا کردن متن در کد کلید را نمی‌شکند. جاهای متغیر با `{n}` و
`{name}` نوشته می‌شوند.

برای افزودن متن تازه: در کد `t('متن فارسی')` بنویسید و همان رشته را با ترجمه‌اش
به `EN` در `i18n.js` اضافه کنید. برای یافتن متن‌های بی‌ترجمه:

```bash
node -e "const a=require('fs').readFileSync('public/js/app.js','utf8'),i=require('fs').readFileSync('public/js/i18n.js','utf8');
const fa=/[\u0600-\u06FF]/, keys=new Set([...a.matchAll(/(?<![\w$])t\('((?:[^'\\]|\\.)*)'/g)].map(m=>m[1]).filter(k=>fa.test(k)));
const have=new Set([...i.matchAll(/^\s*'((?:[^'\\]|\\.)*)':/gm)].map(m=>m[1]));
const miss=[...keys].filter(k=>!have.has(k)); console.log(miss.length?miss:'همه ترجمه دارند');"
```

## فونت

متن فارسی روی **وزیرمتن** می‌نشیند که محلی میزبانی می‌شود (`public/fonts/`)،
نه از CDN — هم برای اینکه در قطعی اینترنت جهانی برنامه درست بالا بیاید و هم
چون فونت پیش‌فرض دستگاه روی هر گوشی فرق می‌کند. مجوزش SIL OFL 1.1 است و
متن کامل آن کنار خود فایل‌ها در `public/fonts/vazirmatn-LICENSE.txt` هست.

## اجرا

```bash
npm install
npm start           # روی http://localhost:3000
```

سپس در مرورگر باز کنید و ثبت‌نام کنید. **نخستین حسابی که ثبت‌نام می‌کند به‌صورت
خودکار مدیر و تاییدشده است**؛ بقیه‌ی کاربران باید از پنل مدیریت تایید شوند.

پنل مدیریت: `http://localhost:3000/admin`

## پاکسازی داده‌ها

به‌صورت پیش‌فرض **خودکار نیست**: مدیر هر وقت بخواهد از پنل، دکمه‌ی «پاکسازی همین
حالا» را می‌زند.

در هر پاکسازی این‌ها **حذف** می‌شوند: همه‌ی پیام‌ها (متن و عکس) و فایل‌های آپلودشده.
این‌ها **باقی می‌مانند**: حساب‌های کاربری، تاییدهای مدیر، گروه‌ها و عضویت‌ها.

اگر خواستید خودکار شود، تعداد روز را در `CLEANUP_INTERVAL_DAYS` بگذارید (مثلاً `7`).
زمان‌بند داخل خود سرور اجرا می‌شود و اگر سرور موقع موعد خاموش باشد، در نخستین
اجرای بعدی جبران می‌کند.

## اعلان‌ها

| جا | چطور کار می‌کند |
| --- | --- |
| کروم اندروید / PWA | از طریق سرویس‌ورکر (`showNotification`) — تنها راهی که در اندروید جواب می‌دهد |
| مرورگر دسکتاپ | همان، با fallback به `Notification` |
| اپ اندروید (APK) | اعلان بومی از طریق پل `AndroidBridge`، چون WebView اصلاً Notification API ندارد |

اعلان وقتی نمایش داده می‌شود که برنامه در پیش‌زمینه نباشد. در اندروید ۱۳ به بالا،
اپ هنگام ورود اجازه‌ی `POST_NOTIFICATIONS` را می‌گیرد.

> محدودیت: اپ اندروید اعلان را تا وقتی پروسه‌اش زنده است (حتی در پس‌زمینه) نشان
> می‌دهد. برای اعلان پس از بسته شدن کامل برنامه یا به سرویس پیش‌زمینه‌ی دائمی
> نیاز است (که اعلان همیشگی و خاموش کردن بهینه‌سازی باتری می‌خواهد) یا به FCM و
> سرویس‌های گوگل — هیچ‌کدام عمداً اضافه نشده‌اند.

## استقرار روی سرور (دسترسی از هر جا)

روی سروری که از قبل سایت دیگری دارد (پورت ۸۰ و ۴۴۳ را نمی‌گیرد):

```bash
sudo bash deploy/deploy-vhost.sh chat.example.com you@mail.com
```

روی سرور خالی، همراه HTTPS خودکار با Caddy:

```bash
sudo bash deploy/deploy.sh chat.example.com you@mail.com
```

راهنمای کامل — شامل استقرار با داکر، nginx، systemd، پشتیبان‌گیری، سرور پشتیبان و
اینکه در هر نوع قطعی شبکه چه چیزی بالا می‌ماند — در [`deploy/README.md`](deploy/README.md).

## نصب روی اندروید

دو راه دارید؛ هر دو به همین سرور وصل می‌شوند.

### ۱) نصب PWA (بدون بیلد)

در کروم اندروید نشانی سرور را باز کنید و از منو «Add to Home screen» را بزنید.
برنامه تمام‌صفحه و با آیکون خودش اجرا می‌شود.

> برای نصب PWA و کارکرد دوربین، سرور باید روی `https` باشد (یا `localhost`).

### ۲) نصب فایل APK آماده

> **کلید امضای اپ را جایی امن نگه دارید.** فایل `android/messenger-release.jks`
> عمداً در مخزن نیست (در `.gitignore` است). اگر گم شود، APK تازه با کلید دیگری
> امضا می‌شود و اندروید اجازه نمی‌دهد روی نسخه‌ی نصب‌شده به‌روزرسانی شود —
> کاربر باید اول حذفش کند. یک نسخه‌ی پشتیبان از این فایل و رمزش بگیرید.

فایل ساخته‌شده و امضاشده: [`dist/9chat-1.3.apk`](dist/9chat-1.3.apk) — نسخه‌ی ۱.۳؛ مرجع گواهی سرور داخلش جاسازی شده تا در نبود اینترنت جهانی هم کار کند

آن را روی گوشی کپی کنید و نصب کنید (اجازه‌ی «نصب از منابع ناشناس» لازم است، چون از
گوگل‌پلی نصب نمی‌شود). هنگام نخستین اجرا نشانی سرور را می‌پرسد.

### ۳) بیلد اپ اندروید

پوشه‌ی `android/` یک پروژه‌ی کامل Android Studio است که وب‌اپ را در یک WebView
تمام‌صفحه نشان می‌دهد و انتخاب عکس از گالری/دوربین، دکمه‌ی بازگشت و کشیدن برای
تازه‌سازی را به سیستم‌عامل وصل می‌کند.

```bash
# پوشه‌ی android/ را در Android Studio باز کنید، یا:
cd android
echo "sdk.dir=$ANDROID_HOME" > local.properties
gradle assembleDebug         # خروجی: app/build/outputs/apk/debug/app-debug.apk
```

برای ساخت نسخه‌ی امضاشده‌ی release، فایل `android/keystore.properties.example` را به
`keystore.properties` کپی کنید، مقادیر انبار کلید خودتان را بگذارید و
`gradle assembleRelease` را اجرا کنید. انبار کلید را جایی امن نگه دارید: برای
به‌روزرسانی همان برنامه روی گوشی‌ها، نسخه‌ی بعدی باید با همان کلید امضا شود.

نشانی پیش‌فرض سرور `http://10.0.2.2:3000` است (یعنی `localhost` رایانه از دید
شبیه‌ساز اندروید). برای دستگاه واقعی، هنگام نخستین اجرا نشانی سرور از شما پرسیده
می‌شود و بعداً هم از صفحه‌ی خطا قابل تغییر است. برای تغییر پیش‌فرض، مقدار
`DEFAULT_SERVER_URL` را در `android/app/build.gradle.kts` عوض کنید.

> فایل `gradle-wrapper.jar` در مخزن نیست؛ Android Studio آن را خودش می‌سازد،
> یا با `gradle wrapper` بسازید.

## ساختار پروژه

```
server/
  index.js      راه‌اندازی HTTP، استاتیک و مسیرها
  db.js         شِمای SQLite
  auth.js       رمز، نشست و نگهبان‌های دسترسی (تاییدشده / مدیر)
  store.js      همه‌ی پرس‌وجوهای پایگاه‌داده
  routes.js     API گفتگو، پیام و عکس
  admin.js      API پنل مدیریت
  realtime.js   وب‌سوکت: پخش پیام، حضور، «در حال نوشتن»
  cleanup.js    پاکسازی هفتگی
  images.js     تشخیص فرمت و ابعاد عکس از روی بایت‌ها
public/         وب‌اپ (PWA)، پنل مدیریت، سرویس‌ورکر و آیکون‌ها
android/        اپ اندروید (Kotlin + WebView)
scripts/        ابزارهای خط فرمان
test/           آزمون سرتاسری با node:test
```

## امنیت

| | |
| --- | --- |
| رمزها | bcrypt، حداقل ۸ نویسه |
| بازیابی رمز | خودکار نیست — ایمیل و شماره گرفته نمی‌شود؛ مدیر از پنل رمز تازه می‌گذارد |
| نشست | توکن تصادفی ۲۵۶ بیتی، کوکی `HttpOnly` + `SameSite=Lax` و `Secure` پشت HTTPS |
| حدس رمز | محدودیت نرخ روی آی‌پی و روی نام کاربری؛ شمارنده با ورود موفق صفر می‌شود |
| افشای نام کاربری | زمان پاسخِ ورود همیشه یکسان است (حتی وقتی کاربر وجود ندارد) |
| شمارش کاربران | گفتگو فقط با نام کاربری دقیق ساخته می‌شود، نه شناسه‌ی عددی |
| عکس‌ها | نوع فایل از روی بایت‌ها تشخیص داده می‌شود، نه نام یا `Content-Type` |
| نشانی عکس | توکن جدا و ۲۴ ساعته با امضای HMAC — نه توکن نشست |
| XSS | `Content-Security-Policy` سخت‌گیرانه؛ هیچ اسکریپت inline و هیچ منبع بیرونی نیست |
| وب‌سوکت | سقف اندازه‌ی پیام و بررسی مبدأ |
| گروه | فقط سازنده می‌تواند عضو اضافه کند |
| مسدودسازی | بی‌درنگ همه‌ی نشست‌ها و اتصال زنده‌ی کاربر را می‌بندد |

برنامه پشت یک پراکسی (nginx) انتظار می‌رود و فقط به یک هاپ اعتماد می‌کند، تا
آی‌پی کلاینت با هدر جعل نشود. برای استفاده‌ی واقعی HTTPS الزامی است.
