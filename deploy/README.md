# استقرار پیام‌رسان

| وضعیت سرور | اسکریپت | چه می‌کند |
| --- | --- | --- |
| **سرور از قبل سایت دارد** | `deploy/deploy-vhost.sh` | کنار nginx موجود می‌نشیند، پورت ۸۰/۴۴۳ را نمی‌گیرد |
| سرور خالی است | `deploy/deploy.sh` | Caddy را با HTTPS خودکار روی ۸۰/۴۴۳ بالا می‌آورد |
| بدون داکر | `deploy/messenger.service` | اجرا با systemd |
| بدون دامنه / بدون اینترنت | `npm start` | اتصال با IP در شبکه‌ی محلی |

> ⚠️ اگر روی سرور سایت دیگری دارید، **`deploy.sh` را اجرا نکنید** — Caddy پورت ۸۰ و
> ۴۴۳ را می‌گیرد و آن سایت‌ها از کار می‌افتند. از `deploy-vhost.sh` استفاده کنید.

## ۰) سروری که از قبل سایت دارد (حالت امن)

```bash
sudo bash deploy/deploy-vhost.sh 9chat.ir you@mail.com
```

این اسکریپت عمداً محافظه‌کار است:

- برنامه فقط روی `127.0.0.1` گوش می‌دهد؛ پورت ۸۰ و ۴۴۳ دست وب‌سرور فعلی می‌ماند.
- اگر پورت ۳۰۰۰ مشغول باشد، خودش پورت آزاد بعدی را برمی‌دارد.
- هیچ فایل کانفیگ موجودی را تغییر نمی‌دهد؛ فقط یک فایل تازه به نام همان دامنه می‌سازد.
- اگر فایلی با آن نام از قبل باشد، متوقف می‌شود و چیزی نمی‌نویسد.
- پیش از اعمال، `nginx -t` می‌گیرد و در صورت خطا فایل تازه را پاک می‌کند.
- در پایان `reload` می‌کند نه `restart`، پس سایت‌های دیگر حتی یک لحظه هم قطع نمی‌شوند.
- گواهی HTTPS را فقط برای همین دامنه می‌گیرد.

اگر وب‌سرور سرور apache است، اسکریپت متوقف می‌شود و مراحل دستی را چاپ می‌کند
(قالبش در `deploy/apache-vhost.conf.template` هست).

## ۱) استقرار با داکر (پیشنهادی)

پیش‌نیاز: یک سرور با IP عمومی و یک رکورد `A` از دامنه‌تان به آن IP.

```bash
git clone https://github.com/siamaklahouri/Chat.git
cd Chat
git checkout claude/modest-franklin-z9jw2d
sudo bash deploy/deploy.sh chat.example.com you@mail.com
```

همین. اسکریپت داکر را (در صورت نبود) نصب می‌کند، بررسی می‌کند دامنه واقعاً به این
سرور اشاره کند، برنامه و Caddy را بالا می‌آورد و Caddy خودش گواهی Let's Encrypt را
می‌گیرد و تمدید می‌کند.

- برنامه: `https://chat.example.com`
- پنل مدیریت: `https://chat.example.com/admin`
- **نخستین حسابی که ثبت‌نام کند خودکار مدیر می‌شود** — بلافاصله پس از بالا آمدن بسازیدش.

پشتیبان‌گیری: `bash deploy/backup.sh` (یک فایل `tar.gz` از پایگاه‌داده و عکس‌ها).

برای اجرای خودکار هفتگی پشتیبان‌گیری:

```
0 3 * * 1 cd /opt/Chat && bash deploy/backup.sh /var/backups/messenger
```

## ۲) دسترسی از بیرون شبکه

برای اینکه از هر جایی وصل شوید سه چیز لازم است و هر سه در روش بالا هست:
IP عمومی، دامنه‌ای که به آن اشاره کند، و HTTPS. پورت‌های ۸۰ و ۴۴۳ باید در فایروال
سرور باز باشند:

```bash
sudo ufw allow 80,443/tcp
```

> HTTPS اختیاری نیست: بدون آن نه PWA روی اندروید نصب می‌شود، نه دوربین کار می‌کند،
> و رمزها بدون رمزنگاری رد و بدل می‌شوند.

## ۳) وقتی دسترسی شبکه محدود می‌شود

این برنامه هیچ وابستگی بیرونی ندارد — نه CDN، نه فونت از گوگل، نه سرویس اعلان.
هر چه لازم دارد از همان سروری می‌آید که خودتان بالا آورده‌اید. پس دسترسی‌پذیری‌اش
فقط به این بستگی دارد که «مسیر شبکه بین گوشی و سرور» برقرار باشد.

| وضعیت | سرور خارج از کشور | سرور داخل کشور | سرور روی شبکه‌ی محلی |
| --- | --- | --- | --- |
| عادی | ✅ | ✅ | ✅ (فقط داخل همان شبکه) |
| قطع اینترنت بین‌الملل | ❌ از داخل در دسترس نیست | ✅ | ✅ |
| قطع کامل اینترنت | ❌ | ❌ | ✅ |
| اختلال یک اپراتور | ✅ با اپراتور دیگر | ✅ با اپراتور دیگر | ✅ |

نتیجه‌ی عملی:

1. **سرور اصلی را داخل کشور بگذارید.** هم در حالت عادی از خارج در دسترس است، هم
   اگر ارتباط بین‌الملل قطع شود برای کاربران داخل بالا می‌ماند.
2. **سرور خارج را پشتیبان نگه دارید** (`deploy/sync-standby.sh`) تا اگر سرور اصلی
   از کار افتاد، با تغییر رکورد DNS به آن سوییچ کنید. TTL دامنه را روی ۳۰۰ ثانیه
   بگذارید تا سوییچ سریع اعمال شود.
3. **برای قطع کامل، نسخه‌ی شبکه‌ی محلی را آماده داشته باشید:** برنامه را روی یک
   لپ‌تاپ یا رزبری‌پای وصل به مودم/روتر اجرا کنید (`npm start`). هر کسی که به آن
   وای‌فای وصل باشد با `http://<IP آن دستگاه>:3000` چت می‌کند — بدون هیچ اینترنتی.
   در اپ اندروید، نشانی سرور از داخل خود برنامه قابل تغییر است، پس سوییچ بین
   سرور اینترنتی و سرور محلی فقط عوض کردن یک نشانی است.

نکته‌ی صادقانه درباره‌ی دو سرور هم‌زمان: دو نسخه‌ی فعال، دو پایگاه‌داده‌ی جداگانه
دارند و پیام‌هایشان با هم ادغام نمی‌شود. به همین دلیل `sync-standby.sh` یک‌طرفه است
و سرور پشتیبان تا لحظه‌ی سوییچ «سرد» می‌ماند. ادغام دوطرفه به معماری کاملاً
متفاوتی نیاز دارد که برای این اندازه از برنامه ارزشش را ندارد.

### زیردامنه‌ها

اگر هر دو سرور را می‌خواهید، ساده‌ترین کار دو زیردامنه است:

```
chat.example.com   →  IP سرور اصلی
alt.example.com    →  IP سرور پشتیبان
```

و به کاربران بگویید اگر اولی بالا نیامد، در اپ نشانی دومی را بگذارند.

## متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
| --- | --- | --- |
| `PORT` | `3000` | پورت |
| `DATA_DIR` | `./data` | پوشه‌ی داده (پایگاه‌داده + عکس‌ها) |
| `MAX_IMAGE_BYTES` | `8388608` | بیشینه‌ی حجم هر عکس |

## به‌روزرسانی

```bash
git pull
docker compose -f deploy/docker-compose.yml up -d --build
```

داده‌ها روی والیوم جداگانه‌اند و با به‌روزرسانی پاک نمی‌شوند.
